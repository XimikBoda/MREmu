# MREmu WebAssembly Audio Subsystem Documentation

This document describes the browser audio architecture for **MREmu**, detailing how emulated audio generated by `libADLMIDI` is bridged to the browser Web Audio API without native desktop audio library dependencies.

---

## 1. Emulator Audio Generation

In native MREmu, audio is synthesized using `libADLMIDI` (OPL3 software synthesizer) inside `MREngine/Audio.cpp`:
- **Synthesis:** Generates 16-bit signed PCM audio buffers (`int16_t`).
- **Sample Rate:** Fixed at `44100` Hz.
- **Channels:** Stereo (`2` channels).

In the WebAssembly target, `web/src/audio/audio_wasm.cpp` exposes the PCM buffer pointers directly to JavaScript via exported C functions without modifying native source code:
- `mremu_wasm_get_audio_buffer()`: Returns pointer to raw 16-bit PCM audio memory (`int16_t*`).
- `mremu_wasm_get_audio_sample_rate()`: Returns `44100`.
- `mremu_wasm_get_audio_channels()`: Returns `2`.

## 2. Web Audio API Integration Pipeline

```
+---------------------------+
| libADLMIDI OPL3 Synthesizer |
|  (16-bit PCM 44.1kHz)     |
+-------------+-------------+
              |
              v
+---------------------------+
| WASM Linear Memory Heap   | (Module.HEAP16)
+-------------+-------------+
              |
              v
+---------------------------+
| Web Audio ScriptProcessor | (Converting int16 [-32768, 32767] to float [-1.0, 1.0])
+-------------+-------------+
              |
              v
+---------------------------+
| Browser Speakers          | (audioCtx.destination)
+---------------------------+
```

In `web/index.html`, JavaScript processes PCM samples during the `onaudioprocess` callback:

```javascript
audioNode.onaudioprocess = function(e) {
  var outputL = e.outputBuffer.getChannelData(0);
  var outputR = e.outputBuffer.getChannelData(1);

  var bufPtr = getAudioBuffer();
  if (bufPtr) {
    var heap16 = Module.HEAP16;
    var startIdx = bufPtr >> 1;

    for (var i = 0; i < bufferSize; i++) {
      // Normalize 16-bit signed integer to float range [-1.0, 1.0]
      outputL[i] = (heap16[startIdx + i * 2] || 0) / 32768.0;
      outputR[i] = (heap16[startIdx + i * 2 + 1] || 0) / 32768.0;
    }
  }
};
```

## 3. Autoplay Restrictions & "Enable Audio" Control

Modern web browsers block `AudioContext` playback until an explicit user gesture occurs.

To comply with browser autoplay policies:
1. An explicit **"🔊 Enable Audio"** button is provided in `web/index.html`.
2. Upon user interaction (`enableAudio()`), `audioCtx = new AudioContext({ sampleRate: 44100 })` is instantiated and `audioCtx.resume()` is called.
3. The button updates visually to **"🔊 Audio Enabled"** once the Web Audio destination is connected.

---

## 4. Latency Management

To minimize audio latency while preventing buffer underruns:
- Buffer size is set to `2048` samples (~46ms frame window at 44.1kHz).
- The `ScriptProcessorNode` streams data synchronously from the WASM linear memory heap.

---

## 5. Native Audio Preservation

Native desktop audio streaming (`MREngine::Audio` using SFML `sf::SoundStream` and OpenAL) remains completely untouched and unaffected.
