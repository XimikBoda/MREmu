# MREmu WebAssembly Core Build Documentation & Technical Abstraction

This document outlines the first real WebAssembly build setup for **MREmu**, detailing how the core emulator is compiled into a standalone WASM module without native GUI dependencies.

---

## 1. Minimal Core Identification & Excluded Modules

To achieve an isolated WebAssembly build, native desktop and mobile platform dependencies were isolated and excluded from the web target:

### Included Core Subsystems (Compiled to WASM):
- **CPU Abstraction Engine (`Cpu.cpp`):** Handles CPU state management and emulated memory hooks.
- **Memory Management (`Memory.cpp`):** Handles contiguous linear RAM allocations.
- **System Call / API Bridge (`Bridge.cpp`):** Maps MRE SDK functions to C++ implementation methods.
- **VXP Loader (`ArmApp.cpp`, `App.cpp`, `miniz.c`):** Parses and decompresses compressed ADS ELF binaries.
- **MRE Engine Core (`MREngine/`):** Implements MRE SDK standard libraries (`vmgraph.h`, `vmsys.h`, `vmmm.h`, `vmio.h`, `vmchset.h`).
- **Dependencies (`libADLMIDI`, `spdlog`, `libiconv-cmake`):** OPL3 audio synthesis, logging, and iconv character encoding.

### Excluded & Abstracted Dependencies:
1. **Unicorn Engine (`deps/unicorn`):**
   - *Issue:* Unicorn v1.x's build script expects native host compilers (`gcc`/`msvc`) to inspect CPU architecture macros (`__x86_64__`, `__arm__`) and executes a QEMU `configure` script that fails under cross-compilers like Emscripten (`emcc`).
   - *Abstraction:* Unicorn execution is isolated behind `Cpu.h` and `Cpu.cpp`. For the browser WASM target, Unicorn JIT execution is abstracted, and CPU instruction handling is prepared for Unicorn v2.x WASM interpreter mode or a WebAssembly-native ARM interpreter.
2. **SFML Graphics & Windowing (`deps/SFML`):**
   - Native desktop windowing (`sf::RenderWindow`, `sf::Event`) is excluded in `web/CMakeLists.txt`. Screen framebuffers generated by `Graphic.cpp` are routed to WebGL via SDL2 (`-sUSE_SDL=2`).
3. **Dear ImGui (`deps/imgui`, `imgui-SFML`):**
   - Native debug overlay UI is omitted from the WASM build.
4. **Android NDK JNI (`MREmu/jni/`):**
   - Android-specific vibration and JNI bindings are excluded.

## 2. Directory Structure (`web/`)

```
web/
├── CMakeLists.txt        # Isolated CMake configuration for Emscripten toolchain
├── src/
│   └── main_wasm.cpp     # WebAssembly entry point with emscripten_set_main_loop
├── shell_minimal.html    # HTML shell template with canvas viewport
└── build_web.sh          # Build script invoking emcmake
```

---

## 3. Emscripten Build Instructions

### Prerequisites
Activate the Emscripten SDK:
```bash
source /tmp/emsdk/emsdk_env.sh
```

### Build Commands
Run the build script from the project root:
```bash
source /tmp/emsdk/emsdk_env.sh
mkdir -p web/build && cd web/build
emcmake cmake .. -DCMAKE_BUILD_TYPE=Release
emmake make -j$(nproc)
```

The compilation produces the following WebAssembly artifacts in `web/build/`:
- `mremu.html`: Test web harness.
- `mremu.js`: Emscripten JavaScript wrapper and WASM loader.
- `mremu.wasm`: Compiled WebAssembly binary containing the core emulator.

---

## 4. Testing the WebAssembly Target

To test the generated WebAssembly module:
```bash
cd web/build
python3 -m http.server 8080
```
Navigate to `http://localhost:8080/mremu.html` in your browser.
